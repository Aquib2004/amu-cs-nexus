# AMUCS Nexus — Product Roadmap (Student Portal)

This is the execution plan for turning AMUCS Nexus into a full student portal.
It is deliberately **phased and honest**: features that need external services,
live AMU data, or student authentication are marked as such rather than faked.

## Guiding rules
1. Build one vertical slice at a time; verify each before the next.
2. Never invent official data — everything must trace to an indexed source or be
   clearly "unavailable / not integrated yet".
3. External portals (Controller of Examinations) are linked/proxied carefully,
   respecting the target site's frame policy and the fact that result lookups
   require a student's own session.

## Phased plan

### Phase 4 — Controller of Examinations & NEP (partial, in progress)
- ✅ `/exams` page with official links + optional embedded view (done).
- 🔜 NEP (National Education Policy) information section: a curated, cited
  notices/documents view under "NEP cell" (data must come from indexed official
  notices, not invented).
- 🔜 Real result fetching is **not possible client-side**: the CCAE portal is a
  login/session system. A deployable integration would need official agreement
  or a student-provided session — out of scope for a public open-source site.

### Phase 5 — Search, AI assistant, citations (core already works)
- Universal Search box (matches `/api/search`). ✅ backend; 🔜 top-level UI.
- AI College Assistant = `/chat` (grounded). ✅; 🔜 wire a real LLM provider
  (with 429/retry/fallback) so answers can be generated by a model while still
  citing sources.
- Official source/citation for every answer. ✅ backend.

### Phase 6 — Student Dashboard
- List the 44 features: start with Student Profile + Personalized Notices +
  Deadline Tracker as a **dashboard** (needs a `Student`/`Profile` + auth model
  and a `feedback`/`todo` table). Track with `feedback` and `todo` models.

### Phase 7 — Academic data
- Courses, Syllabus, Exam Schedule, Class Timetable, Academic Calendar —
  ingest the official department syllabus/exam pages (reuse ingestion pipeline),
  add models + endpoints + simple tables/calendar views.

### Phase 8 — Life & services directory
- Library / Hostel / Fees / Placements / Contacts / Map / Events — a
  **directory app**: one `Entry` model + admin-managed content + filters. No
  live API needed; data is curated and linked to sources.

### Phase 9 — Platform polish
- Mobile-first responsive, accessibility (labels, focus, semantic HTML — mostly
  present), multilingual (i18n layer), FAQ/Help, feedback (#feedback), Google
  Calendar export button (links to `.ics`), PDF/Notice viewer (built-in).

### Phase 10 — Admin & ingestion UI + RAG knowledge base
- Admin dashboard over the existing APIs (CRUD for entries/notices).
- College Data Ingestion System UI that runs the ingestion pipeline and shows
  sourced documents feeding the AI/RAG knowledge base.

## Requirements before "complete"
1. Authentication (students/staff) to personalize profile, notices, deadlines.
2. Live ingestion of official AMU pages+PDFs (respecting the site) OR a
   curated, cited dataset.
3. A real LLM (+ embedding) provider for production-quality answers.
4. Running PostgreSQL + pgvector and a deployment target (Docker/CI).
5. Signed-off scope on which student-specific integrations (results, fees,
   attendance) can be built, given AMU's systems are session/login-based.

## Suggested next milestone
Build the **Student Dashboard** skeleton: add `StudentProfile`, `Todo`,
`Feedback` models + a `/account` page and a home dashboard, wired to the
existing search/notices/chat. Say **"start the dashboard"** to begin.
